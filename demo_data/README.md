# Demo Data — UI Testing

Generated by `scripts/generate_demo_data.py` (re-run with `python -m scripts.generate_demo_data`).

Files in this folder match the pipeline's detector/extractor column signatures exactly,
so they can be uploaded through the UI like real evidence:

| File | Purpose |
|------|---------|
| `tower_dump_dummy.csv` | 16 Surat towers (Airtel / Vi / BSNL / Jio) with azimuth, beamwidth, range |
| `airtel_cdr_dummy.csv` | Airtel-format CDR — suspect `919876543210` moving across Surat (6 bursts × 4 towers) |
| `spot_dump_dummy.csv` | Spot-dump format of the same journey (extra source for comparison) |

Each burst records calls on 3–4 nearby towers within minutes of each other. The builder
merges those into a single ≥3-tower frame, so the multilateration engine produces one
confidence fix per burst — a 6-point movement path with heatmap zones.

## How to test from the UI

1. Start the stack (backend + `npm run dev`), log in / register an officer.
2. Create an investigation case.
3. Upload `tower_dump_dummy.csv` **first**, then `airtel_cdr_dummy.csv`
   (tower records must exist for the builder to join CGIs).
4. Open the case → **Run Multilateration Engine**.
5. Toggle **Heatmap**, play the **timeline scrubber**, and check the
   **"around {area}" narrative banner** (reverse geocoding via Nominatim).

> Note: reverse geocoding calls OSM Nominatim (1 req/s limit). First load may be slow;
> results are cached per ~44 m grid cell and reused by exports (CSV/PDF area column).
